Features

Everything that makes Critique great

If you've used Critique, Twigg will feel familiar on day one.

small CLs → stacked commits

Small, dependent changes

Ship work as a stack of small commits that build on each other. Each one is reviewed and merged independently.

cl/67 → c/67v0, c/67v1, ...

Stable versioned identifiers

When a commit is pushed to the server, it gets a number: c/67v0. Amend it, push it, and c/67v1 is created. No version is ever lost.

snapshots → commit versions

Iterate under review

Address feedback by pushing a new version of the same commit. Reviewers see the changes and how they evolved, version to version.

code ownership → OWNERS files

Hierarchical ownership

Declare who owns each part of the repo. Ownership cascades down directories.

presubmits / rollouts → built-in CI/CD

Tests on every commit

Path-aware jobs run on every commit, with unlimited minutes.

patch in a CL → tw pull c/67

Easy multiplayer

tw pull c/67, tw amend, tw push: that's all it takes to contribute to someone else's commit.

branches · unfinished rebase → gone

Simpler than Git

Commits and commit versions: that's it. No branches, no staging areas, no unfinished rebase states.

gradual adoption → git mirror

Risk-free to try

Submitted changes are automatically pushed to your mirrored Git repo, so switching off costs nothing.
